# AI 辅助用例生成记录（LLM 变异扩写）

> 对标评审标准"AI 能力应用水平：AI 辅助生成测试用例"的实证记录。全流程可复现：
> `python scripts/gen_cases_by_llm.py --seed 12` → `python scripts/run_expanded_cases.py`

## 1. 流程（人机协同）

```
黄金用例种子（12 条功能用例）
   │  LLM 变异生成（glm-4.5-air，temperature=0.7）
   │  策略：同义改写 / 口语化 / 噪声错别字 / 场景化包装，每种子 3 条
   ▼
36 条扩展用例（datasets/golden/functional_llm_expanded.csv）
   │  自动抽审（双校验）：
   │   ① 关键数字强断言（strict_numbers 归一化匹配）
   │   ② LLM-as-a-Judge 三元判定（≥0.5 通过）
   ▼
抽审结果（reports/data/expanded_case_review.csv）→ 采纳入库
```

## 2. 结果

| 指标 | 数值 |
|---|---|
| 种子用例 | 12 条（覆盖校历/学籍/选课/成绩/奖助/宿舍/校卡/图书馆等主题） |
| 生成变体 | 36 条 |
| 自动抽审通过 | **36/36（100%）**——被测智能体在变异表述下全部保持答案正确 |
| 判定口径 | 关键数字断言 + Judge 三元判定双重校验，二者全过才计通过 |

## 3. 结论与价值

1. **用例规模化**：以 12 条人工种子扩展出 36 条语义等价用例（3 倍杠杆），覆盖真实用户多样化的表述习惯；
2. **鲁棒性验证**：36/36 通过同时说明智能体对同义/口语/噪声表述的检索与理解具备稳定性，变异用例集可直接并入回归测试资产；
3. **人机协同边界**：LLM 负责扩写、断言与 Judge 负责把关、人工负责种子设计与最终抽认——每一环节的产物均可审计。
