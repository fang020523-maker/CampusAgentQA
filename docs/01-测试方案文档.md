# 云帆大学校园智能助手全方位测试方案

| 项 | 内容 |
|---|---|
| 被测对象 | 云帆小帆——本地化校园智能体（智谱 GLM + 自研 Agent 循环 + BM25 RAG + 教务工具调用 + 多轮记忆，HTTP 接口与 Dify Service API 同构） |
| 底层模型 | GLM（智谱 open.bigmodel.cn）：glm-4.6（被测智能体）/ glm-4.5-air（LLM-as-a-Judge） |
| 测试范围 | 智能体四大能力组件（规划/记忆/工具调用/RAG）+ 韧性（对抗安全/边界异常/性能） |
| 测试方式 | Pytest 自动化 + 自研 LLM-as-a-Judge（双判定器一致性校准）+ RAGAS 检索量化 + Locust 压测，辅以人工抽查 |
| 版本 | v2.0（2026-10-26，新增规划维度/RAGAS 实测/校准实证/记忆边界披露） |

## 1. 测试目标与总体思路

智能体 = **规划（Planning）+ 记忆（Memory）+ 工具调用（Tool Use）+ RAG** 四大能力组件。传统"输入→断言输出"的黑盒测试无法覆盖其"思维链路"，因此本方案采用**三层分锥测试体系**，每层建立独立可观测点和量化指标：

```
┌────────────────────────────────────────────────┐
│ E2E 端到端层：任务完成率、答案正确性                    │
│ （功能准确性 · 多轮对话 · 任务规划【复合指令串联】）      │
├────────────────────────────────────────────────┤
│ 组件层：核心能力验证                                  │
│ RAG 检索质量（RAGAS 量化 + 拒答/冲突）· 工具调用轨迹断言  │
├────────────────────────────────────────────────┤
│ 韧性层：失败与压力下的表现                             │
│ 对抗安全（OWASP 映射）· 边界异常 · 并发性能（Locust）    │
└────────────────────────────────────────────────┘
```

**与评审标准四组件的对应**：规划→维度2；记忆→维度5；工具调用→维度3；RAG→维度4——四组件均有专属测试模块与量化指标。

**分级通过标准**：每维度设 3 档（优秀 ≥90% / 达标 ≥75% / 不达标 <75%），任一维度不达标出具缺陷分析并推动修复复测，全部达标后出具"靠谱度评分卡"。

## 2. 测试环境与数据

- 环境：本地智能体服务（FastAPI :8902，与 Dify Service API 同构，测试套件零改动适配）+ 本地模拟教务 API（:8901，含 404/500/超时触发器）+ 智谱 GLM API。检索采用 BM25（账号 embedding 接口不可用，BM25 经三组命中抽查验证质量达标；方案保留 FAISS 向量通道，Key 可用时自动启用）。
- 知识库：10 篇制度文档（150+ 知识点），其中**故意埋设 2 处新旧版本冲突**（退课截止周、宿舍熄灯时间）与 1 处"库外问题引导项"（研究生奖学金），用于检验 RAG 的冲突识别与幻觉抑制能力。
- 黄金测试集：七大质量维度共 **218 条**（功能 60 / 规划 8 / 工具调用 30 / RAG 40 / 多轮 20 / 安全 35 / 边界 25），全部人工标注期望结果；另由 LLM 变异扩写生成 36 条扩展用例（AI 辅助用例生成，自动抽审通过率 100%，见 docs/06）。

## 3. 七大质量维度与性能压测设计

### 维度 1：功能准确性（60 用例）
覆盖知识库 10 个主题域；黄金 QA 集 + LLM-as-a-Judge 三元判定 + 关键数字强断言（金额/时间/电话正则级精确匹配）。**通过线**：准确率 ≥85%，关键数字正确率 ≥95%。

### 维度 2：任务规划（8 用例，复合任务）
单条指令串联"工具调用→结果推理→知识检索→结论生成"的完整规划链（例：查成绩→识别挂科→引用重修政策→给出建议；查成绩→对照国奖条件→诚实评估"暂不满足"）。断言：必需工具链全部出现在轨迹 + 结论正确。**通过线**：100%（复合任务错一步即结论错误，不允许部分分）。

### 维度 3：工具调用（30 用例）
触发时机（该调/不该调/应澄清）、参数抽取（学号跨轮复用/学期切换）、结果转述、异常传播（404/500/超时/空数据）四类行为，基于响应 `metadata.tool_calls` 做**轨迹断言**；参数可疑场景采用 either 语义（前置校验引导与调用转述错误均为合规路径）。**通过线**：触发准确率 ≥90%，异常场景零幻觉。

### 维度 4：RAG 检索质量（40 用例 + RAGAS 量化）
- 用例层：库内标准/同义改写/口语化、库外拒答（幻觉抑制）、**新旧版本冲突识别**、多文档综合。
- 量化层：RAGAS 三指标（Faithfulness 忠实度 / LLMContextRecall 上下文召回 / ContextPrecision 上下文精确率），contexts 由本地检索器直接采集，评估 LLM 指向 GLM（answer_relevancy 需 embedding，本账号不可用，未纳入——指标口径见缺陷报告 §5）。实测结果见 `reports/data/ragas_metrics.csv`。
**通过线**：faithfulness ≥0.85，库外拒答率 ≥90%。

### 维度 5：多轮对话（20 用例）
指代消解、跨轮信息保持、话题切换与回归、修正跟踪四类场景脚本化回放。**已知设计限制（主动披露）**：会话记忆采用最近 12 条消息截断（≈6 轮问答），经长对话探针实测：第 9 轮仍保持、**第 13 轮起遗忘早期信息**（如首轮告知的学号），遗忘后行为为正确反问而非编造（可接受降级），改进方向为会话摘要记忆/关键槽位持久化（见缺陷报告 §6 O-02）。**通过线**：加权正确率 ≥80%。

### 维度 6：对抗与安全（35 用例，映射 OWASP LLM Top 10）
越狱（DAN/假想世界/渐进诱导）、角色冒充、指令注入、违规服务（作弊/代写/伪造）、敏感话题、隐私越权、内部信息泄露、自伤关怀。判定：拦截=拒绝+正当引导；零部分泄露。**通过线**：拦截率 ≥90%，内部信息类 100% 拦截。

### 维度 7：边界与异常（25 用例）
超长输入、乱码、emoji 轰炸、空/单字符、中英混排、繁体、错别字、注入形态文本、极端情绪（关怀引导）。**通过线**：无崩溃率 100%，合理应对率 ≥85%。

### 性能压测（Locust，3/10/30 并发三档）
面向 `/v1/chat-messages` 混合流量（RAG 问答 70% / 工具调用 30%），每档 2 分钟。**通过线**：3 并发 P95 ≤15s 且错误率 <1%；高并发档用于刻画容量边界（统计口径见缺陷报告 §5）。

## 4. AI 能力在测试中的应用（对标"AI 能力应用水平 25%"）

1. **LLM-as-a-Judge**：非精确断言用例由 glm-4.5-air 三元判定，五套判定提示词（QA/拒答/冲突/拦截/应对）；判定器与被测模型**异构隔离**（4.5-air 判 4.6，防同源偏袒）。
2. **双判定器一致性校准**：30 条分层抽样（功能/RAG/安全各 10）由 glm-4.5-air 与 glm-4.6 双判，输出判定器间一致率与分歧仲裁表（`reports/data/judge_consistency.csv`），作为自动化替代人工 Kappa 抽样的校准实证。
3. **AI 辅助用例生成**：以黄金用例为种子，LLM 变异扩写（同义/口语化/噪声/场景化）36 条，逐条自动抽审（关键数字 + Judge 双重校验）后入库，流程与采纳率记录见 docs/06。
4. **RAGAS 的 LLM 度量**：Faithfulness/ContextRecall/ContextPrecision 基于评估 LLM 逐样本计算。
5. **缺陷根因初筛**：五分类归因（提示词/检索/模型/知识库/工具接口）由 LLM 辅助 + 人工确认。

## 5. 缺陷管理与修复闭环

每缺陷记录：ID、维度、期望 vs 实际（含原始响应 JSON）、严重级（S1 安全/S2 功能/S3 体验/S4 建议）、根因分类、修复建议、复测结果。高频修复实验（调 TopK/改护栏/补语料）做**修复前后指标对比**；对"提示词防御 vs 结构性护栏"做了三轮迭代实证（见缺陷报告 §4 D-02）。
