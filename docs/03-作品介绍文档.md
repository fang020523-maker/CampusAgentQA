## 一、项目详情及使用方式

### 1.1 项目背景

AI 智能体的自主性（规划、工具调用、记忆、RAG）带来了传统软件测试无法覆盖的质量风险：检索到错误知识给出错误建议、多步执行中"迷路"、被诱导执行非预期操作、工具异常时编造数据。本项目完整实践了"**先造后测**"的赛题要求：先自研搭建一个真实可用的校园智能体应用，再围绕它的全链路设计并执行系统性测试。

### 1.2 被测对象：云帆小帆校园智能助手

| 项 | 说明 |
|---|---|
| 目标用户 | 云帆大学全校学生（以本科生为主），覆盖新生入学高频疑问场景 |
| 核心能力 | ① 制度问答（RAG）：校历、学籍、选课、成绩、奖助、宿舍、图书馆等 10 篇制度文件；② 教务工具调用：成绩单/周课表查询（含错误转述）；③ 任务规划：复合指令串联工具→推理→检索→结论；④ 多轮对话记忆：指代消解、信息保持、修正跟踪 |
| 技术栈 | 智谱 GLM（glm-4.6 对话 + glm-4.5-air 评审）+ 自研 Agent 循环（OpenAI function-calling 协议）+ BM25 检索（字符二元组，免分词依赖）+ FastAPI（接口与 Dify Service API 同构） |
| 安全设计 | 系统提示词 7 条护栏（提示词层）+ 输入侧写作任务结构性拦截（代码层） |

系统架构见 `reports/figures/architecture.png`。

## 二、项目亮点（方法论：「三层分锥 · 轨迹断言」测试法 + 七维靠谱度评分卡）

我们把整个测试方法提炼为**「三层分锥 · 轨迹断言」测试法**：断言对象从"最终输出"下沉到"思维链路轨迹"，评估产出收敛为一张**七维度加权的靠谱度评分卡**。与传统软件测试的本质差异：

| 对比项 | 传统软件测试 | 本方法（智能体测试） |
|---|---|---|
| 断言对象 | 输出值/状态 | **工具调用轨迹 + 检索内容 + 最终答案**三层 |
| 通过标准 | 确定性二值断言 | 关键数字强断言 + **LLM 三元判定（1/0.5/0）** + 轨迹断言组合 |
| 用例设计 | 等价类/边界值 | 增加四组件专属设计：规划复合指令、记忆跨轮脚本、RAG 拒答/**故意埋冲突语料**、安全攻击库 |
| 判定器 | 无需判定器 | LLM-as-a-Judge，**双判定器一致性校准 + 与被测模型异构隔离** |
| 缺陷根因 | 代码逻辑 | 五分类：提示词/检索/模型能力/知识库质量/工具接口 |
| 评测体系自身 | — | 用例变异扩写抽审、框架缺陷台账（11 项）——"测 AI 的体系"也要被验证 |

六大具体亮点：

1. **评审四组件全覆盖**：规划（8 条复合任务，含"查成绩→对照国奖条件→诚实告知不满足"的诚实性场景）、记忆（20 条多轮脚本 + 长对话边界探针）、工具调用（30 条轨迹断言）、RAG（40 条 + RAGAS 量化）——每个组件都有专属测试模块与量化指标。
2. **工具调用轨迹级断言**：验证"该不该调、调的对不对、参数对不对、异常怎么转述"，包括"信息不足应澄清而非虚构参数调用""参数非法时前置校验优于盲目调用"等智能体特有断言语义。
3. **知识库冲突治理测试**：故意埋设 2 处新旧版本冲突（退课截止周、熄灯时间），验证冲突识别与"以最新制度为准"。
4. **「提示词防御不可靠」实证**：文书代写越界请求经两轮提示词加固均失败，输入侧结构性护栏根治，35 条安全用例回归零副作用——为智能体安全分层防护提供实测依据。
5. **量化与用例互补的评估观**：RAGAS faithfulness=0.728（召回 0.929/精确率 0.879）与用例级"零编造"结论的差异，被归因为"模型主动转介建议"与忠实度指标的天然张力——证明量化指标与用例断言应互补而非互替。
6. **测试资产自身的质量管控**：初测 15 个失败中 11 个定位为测试框架缺陷并全部修复留档；36 条 LLM 变异用例 100% 抽审通过；全程证据链（218 份用例 JSON + 8 轮结果 CSV）可审计可复现。

> 注：35 条对抗用例均为**预防性红队测试**——以假设性提问验证智能体的拒绝与引导能力（期望行为=明确拒绝并说明后果），用例本身不构成对越狱、赌博、作弊等行为的任何指导，属安全测试的正向防御实践（映射 OWASP LLM Top 10）。

## 三、AI 能力应用说明

### 3.1 智能体搭建中的 AI 应用

- **提示词设计**：五段式结构（角色/能力边界/回答规范/7 条安全护栏/多轮规范），完整样例见 `agent-app/系统提示词.md`；
- **工作流编排**：自研 Agent 循环"输入护栏预检 → LLM 决策 → 工具执行 → 结果回填 → 再决策"闭环（≤6 轮），每一步可观测可断言；
- **工具配置**：三个工具以 OpenAI function-calling Schema 声明，参数约束（学号 10 位、周次 1-20、学期枚举）下沉到工具协议层。

### 3.2 测试环节中的 AI 应用（人机协同流程）

| 环节 | AI 应用 | 人的角色 |
|---|---|---|
| 用例生成 | LLM 变异扩写 36 条（同义/口语化/噪声/场景化），自动抽审 100% 通过（docs/06） | 设计种子用例与期望、最终抽认 |
| 结果判定 | LLM-as-a-Judge 五套判定提示词；**双判定器（4.5-air vs 4.6）30 样本一致性 100%**，判定器与被测模型异构隔离防偏袒 | 分歧样本仲裁 |
| 量化评估 | RAGAS（Faithfulness/ContextPrecision/ContextRecall），评估 LLM 指向 GLM | 指标口径定义与解读 |
| 缺陷归因 | LLM 辅助五分类归因 | 确认根因、设计修复实验 |

### 附：实用性与推广（迁移指南）

- **平台迁移低成本（设计对齐，未实测）**：被测服务接口结构与 Dify Service API 同构（/v1/chat-messages、conversation_id、metadata.tool_calls），测试套件按平台无关方式编写，切换 `.env` 的 `DIFY_BASE_URL` 即可指向 Dify 应用；因本机网络无法访问 cloud.dify.ai（DNS 污染 + IP 阻断），该迁移路径未在真实 Dify 实例上实测，属设计性声明；
- **场景迁移低成本**：知识库语料、黄金用例集、攻击库均为数据文件，替换为其他领域（法律/医疗/客服）语料与用例即可复用整套测试框架；
- **潜在落地**：高校信息中心智能体验收测试、Agent 开发团队的持续回归门禁、教务/门户系统厂商的出厂质检。
